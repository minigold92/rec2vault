# 국내 STT·회의록 서비스 데이터 처리 조사 (확인일: 2026-11-09)

작성: DomesticDataPolicy. 범위: 삼성 Galaxy AI 텍스트 변환 어시스트, 네이버 클로바노트(개인용/네이버웍스), 네이버클라우드 CLOVA Speech, 리턴제로 RTZR STT API, 다글로(Developers API/웹), 콜라보, 티로.
목적: 녹음(회사 업무 정보 포함 가능)이 서비스 제공자 쪽에서 어떻게 다뤄지는지 비교. 자동화 금지 조항은 이번 조사 대상이 아님.
선행 문서: `docs/research/korean-stt.md`(1차). 그 문서의 "9. 데이터 정책 / 확인 못 함"을 이번에 약관·방침 원문으로 메웠고, 이미 확인된 항목은 출처를 다시 열어 재확인했다.

## 0. 표기 규칙

- **[원문]** 2026-11-09에 약관·개인정보처리방침·도움말·공식 지원문서 본문을 직접 열어 확인한 사실(인용은 따옴표). 법률 판단 아님.
- **[해석]** 원문을 읽고 의미를 풀어 쓴 것. **[추정]** 근거가 불충분한 가정. **[2차]** 블로그·언론·통신사 가이드. **확인 못 함** 찾지 못함(값을 채우지 않음).
- 마케팅 문구는 근거로 쓰지 않았다. 일부 페이지(삼성 약관, 네이버 정책 팝업, RTZR 가입 약관 모달, 다글로·콜라보·티로 정책)는 JS 렌더링이라 헤드리스 브라우저로 본문 텍스트를 추출해 읽었다.
- 등급: **A** 녹음이 기기·자체 서버 밖으로 안 나감 / **B** 외부 처리지만 학습 미사용이 기본(또는 확실한 옵트아웃), 보관이 짧거나 사용자 통제 가능, 사람 검토 없음(오남용 예외는 명시) / **C** 기본값이 학습 사용이거나, 사람 검토가 있거나, 장기 보관이거나, 핵심 항목이 확인 불가.
- "방침에 사람 검토 조항 없음"은 "사람 검토 없음"의 증명이 아니다. 그런 경우 표에는 **확인 못 함**으로 적었다.

[해석] 방침이 "전사 텍스트"만 대상 정보로 적은 것은 오디오 자체가 서버로 가지 않을 가능성을 시사하지만, 같은 삼성 문서(각주 9, samsungsvc)는 "텍스트 변환"에도 네트워크가 필요하다고 한다. 두 서술이 맞지 않아 **전사(STT)가 기기에서 도는지는 확인 못 함.** 한국어 언어 팩 존재 여부도 문서에 없음.

**실기기 검증 방법(판정용):** 비행기 모드 + '기기에서만 데이터 처리' ON 상태에서 한국어 m4a 1건에 대해 ① 텍스트 변환 ② 화자 구분 ③ 요약을 각각 실행해 보고, 되면 오프라인 처리로 본다. 요약만 막히면 STT만 A로 쓸 수 있다.

### 9-1. 이 조사에서 확인하지 못한 것(후속 확인 필요)

- 삼성: ① '기기에서만 데이터 처리' ON에서 한국어 텍스트 변환·화자 구분·요약 동작 여부(실기기), ② 텍스트 변환 어시스트의 서버 측 처리 주체(삼성/Google)와 국가, ③ 학습 사용 여부(방침과 Knox 문서의 상충), ④ 사람 검토, ⑤ 서비스 단위 인증.
- 클로바노트 개인용: 선택 동의 초기 상태, AI 요약 엔진·위탁사, 오남용 모니터링 예외, 동의 철회 후 이미 비식별된 사본 삭제 절차, 인증 범위 포함 여부.
- 네이버웍스 클로바노트: 요약에 쓰는 OpenAI 모델의 호스팅 위치·보관, 네이버 직원의 접근 규정, ZDR.
- CLOVA Speech: 원본 음성 보관 기간, 학습 동의 화면, 사람 접근 규정(음성 데이터 기준), 서비스 단위 인증 범위.
- RTZR: 사람 검토 조항, 인증, 즉시 삭제 API 유무.
- 다글로: API 제13조 옵트아웃, 웹 품질 향상 동의 초기 상태, AssemblyAI 사용 조건, ISO 27001 범위·유효기간.
