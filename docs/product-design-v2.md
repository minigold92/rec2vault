작성 2026-11-09. v1(`product-design-v1.md`)을 독립 검토(`research/design-review-v1.md`, Astra) 결과로 고친 판이다. 근거: 운영 기록(`operations.md`, `contract.md`), 벤치마크(`benchmark.md`), 비슷한 오픈소스 조사(`research/oss-landscape.md`), 사용자 소개 글(`~/Projects/side/aicc/_workspace/2026-11-09-rec-post/맥서기_v2.html`).

- **목적**: 만든 사람만 설치·운영할 수 있는 지금의 파이프라인을, Mac과 안드로이드 폰을 가진 사람이 직접 설치해 매일 쓰는 제품으로 만든다.
- **독자**: 구현 에이전트, 검토자, 방향을 정할 사용자.
- **이 문서로 정할 것**: 출시 기준, 제품 형태, 구현 전에 고정할 계약, 작업 순서와 완료 기준.

**사용자가 정한 것(2026-11-09)**: 1차 대상은 Mac + 안드로이드. 쓰기 쉬움과 어느 정도의 UI 품질이 우선. 다음은 NVIDIA PC, 이후 폰 단독 처리. 요약 엔진은 구독 CLI(Codex·Claude·Gemini)와 로컬 LLM(Ollama). 언어는 한국어·영어를 녹음마다 자동 감지. GitHub 문서는 작동 원리가 이해되게.

## 0. 이름과 말투

- **캐릭터**: 맥서기(맥 + 서기). 1인칭 비서 말투("녹음만 해 주세요. 회의록은 제가 쓸게요.").
- **이름 구조(제안)**: 저장소·패키지 `rec2vault`는 유지하고, **플랫폼 중립 제품 이름 하나 + 한국어 캐릭터 맥서기**로 간다. OS마다 제품 이름을 따로 두는 안은 검색·문서·동반 앱 연결이 약해져 권하지 않는다. 중립 제품 이름과 영어 이름은 충돌 검사 후 정한다(11절).
- **말투 원칙**
  - 화면 문구·알림·README 첫머리·소개 페이지에 쓴다. 상태값·로그·API 값은 캐릭터 말투로 바꾸지 않는다.
  - 오류는 친근한 한 문장 다음에 오류 코드, 실제 상태, 복구 버튼을 둔다. 원인을 모르면 추측을 사실처럼 말하지 않는다(폰 연결 오류를 항상 "같은 와이파이인지 보세요"로 안내하지 않는다).
  - 약속의 범위를 정확히 쓴다. "연결을 마치면 저장 뒤 회의록 **초안**까지 자동으로 만들어요. 중요한 결정과 할 일은 근거를 확인해 주세요." 교정은 "잘못 들은 단어만 고치는 게 원칙이에요"이지 "내용은 절대 안 바뀌어요"가 아니다. 소개 글의 "추가 앱 불필요"는 "녹음 앱은 그대로, 전송 앱은 필요"로 고친다.
  - 영어는 같은 기능 의미를 유지하되 한국어 의인화 문장을 직역하지 않는다.

## 2. 출시 기준과 제품 형태

### 2.1 출시를 둘로 나눈다

| 출시 | 대상 | 통과 조건 |
|---|---|---|
| 개발자 프리뷰 | 터미널·Homebrew를 쓰는 사람 | 깨끗한 Mac 계정에서 `brew install` + 화면 마법사로 첫 회의록. 문서만 보고 따라 함 |
| 일반 사용자 첫 출시 | 터미널을 모르는 Mac + 갤럭시 사용자 | 개발자가 아닌 사람이 도움 없이 설치 → 폰 연결 → 첫 회의록 → 폰에서 결과 확인. 시간·막힌 곳·도움 요청 횟수를 기록하고 기준을 넘음 |

일반 사용자 출시의 폰 연결 방식은 4절의 시험 결과로 정한다. Syncthing 안내로 초심자 시험을 통과하면 Syncthing, 아니면 동반 앱이 선행 조건이다.

### 2.2 형태

**엔진(상주 서비스) + 로컬 웹 화면을 먼저 완성하고, 같은 화면을 Mac 앱 껍데기(Tauri)로 감싼다.**

| 안 | 판단 |
|---|---|
| A. 엔진 + 내장 웹 화면 | 먼저 만든다. 화면 한 벌로 Mac·이후 Windows·Linux, Mac mini 같은 화면 없는 서버에 맞음 |
| B. A + Tauri 껍데기 | 일반 사용자 출시용. 엔진 설치·실행·업데이트·메뉴 막대. 파이썬 실행물을 sidecar로 묶는 방식(공식 문서 https://v2.tauri.app/develop/sidecar/)과 첫 실행 시 받아 오는 방식 중 MLX 의존성에 맞는 쪽을 시험으로 고른다 |
| C. 네이티브 SwiftUI | Mac 전용 제품을 택할 때만. 이후 플랫폼에서 다시 만들어야 해서 지금은 안 함 |

웹 화면 기술: **서버 렌더링 + HTMX + 오디오 재생·실시간 상태(SSE)용 작은 JS.** 화면이 마법사·목록·작업 위주이고 편집기가 없기 때문이다. API(JSON)와 HTML 표시 계층을 나누고, 화면 자산은 로컬에 묶는다(외부 CDN 없음). 대화록 편집이나 오프라인 화면이 실제 요구가 되면 SPA를 다시 검토한다.

## 3. 사용자 여정과 화면


### 3.1 설정 마법사

| 단계 | 화면이 하는 일 | 사용자가 하는 일 | 주의 |
|---|---|---|---|
| 1. 환경 점검 | 칩, 메모리, 디스크, ffmpeg | 없음 | 모자라면 이유·해결법 |
| 2. 모델 받기 | 4개 모델(약 5.2GB) 진행률, 이어받기 | 기다림 | 공간 부족·끊김 상태 정의 |
| 3. 회의록 위치 | Obsidian 볼트 후보 제시(Obsidian 설정 파일의 볼트 목록) | 고르기 | 브라우저 파일 선택은 서버 폴더 선택이 아니다. Mac에서는 앱 껍데기·로컬 실행기가 폴더 선택 창을 열고, 화면 없는 Mac은 후보 목록 + 경로 입력 |
| 4. 요약 엔진 | 설치된 CLI와 Ollama 감지, 제공자별 로그인 상태, 시험 호출 | 고르기, 로그인 | 로그인은 제공자마다 절차·만료·취소가 다르다. "로그인 버튼 한 번"으로 완료 처리하지 않음. 무도구 동작이 확인 안 된 제공자는 표시 |
| 5. 폰 연결 | 4절 | QR 스캔 등 | 기존 녹음 처리 방식을 여기서 고르게 함 |
| 6. 시험 | 새 녹음 도착·단계 진행 실시간 표시 | 5분 이상 녹음 | 남은 시간은 근거가 생기기 전까지 표시하지 않고 단계·경과 시간만 |

### 3.2 평소 화면

| 화면 | 내용 |
|---|---|
| 홈 | 오늘 처리한 녹음, 진행 중 작업(단계·경과 시간), 최근 오류, 폰 연결 상태, 처리 일시정지 |
| 회의록 | 제목·날짜·길이·유형·언어. 열면 요약과 대화록, 근거 시각을 누르면 그 구간 오디오 재생 |
| 작업 | 실패·건너뜀과 사유. "다시 처리"(처음부터), "요약만 다시", "이 녹음 처리하기" |
| 기존 녹음 | 아직 처리하지 않은 녹음 목록(받지 않은 것, 건너뛴 것 구분). 골라서 처리 |
| 설정 | 회의록 위치, 요약 엔진·순서·로컬 전용 모드, 언어(자동/고정), 최소 길이, 처리 시작 시각, 화면 접근 범위, 보존 기간·로컬 데이터 삭제 |

화면 품질 기준: 한 화면 한 가지 일, 상태는 색과 문장을 같이, 키보드 사용·초점·라벨, 좁은 폰 화면, 한/영 줄바꿈, 빈 상태·오류·오프라인 상태를 각각 디자인한다.

## 4. 폰 연결

### 4.1 Syncthing 경로 (지금 동작하는 경로를 자동화)

작업을 나눠 각각 실측한다.

| 단계 | 하는 일 | 먼저 확인할 것 |
|---|---|---|
| 페어링 | Mac 장치 ID QR, 폰 Syncthing-Fork에서 스캔, Mac이 폰 장치 승인 | 양방향 승인 흐름, 기존 Syncthing 설정 보존 |
| 폴더 공유 | Mac이 받기 전용 폴더를 만들고 폰에 공유 요청. 화면이 폰에서 "수락 → 경로 → 보내기 전용"을 그림으로 안내 | 폴더 ID 충돌, Syncthing-Fork 저장 버튼 버그 회피 안내 |
| 기존 목록 얻기 | 폰에 이미 있는 녹음 목록을 Mac이 알아냄 | **내용 전송 없이 목록만 얻을 수 있는가** (예: 받는 폴더를 처음에 전부 무시로 시작해도 상대 색인이 들어오는가). 길이 정보는 색인에 없을 수 있음 |
| 기존 녹음 차단 | 목록을 무시 패턴으로 등록(파일 이름의 와일드카드 문자 이스케이프, NFC/NFD) | 차단 후 새 녹음은 정상 수신되는가 |
| 선택 해제 | 사용자가 고른 기존 녹음만 무시 해제 | 지금 `rec.backfill` 경로 재사용 |

목록만 얻는 것이 불가능하면 약속을 바꾼다. 사용자에게 "기존 녹음도 받기(전송량 표시)" 또는 "동반 앱 사용" 중 고르게 한다.

### 4.2 안드로이드 동반 앱 (타당성 시험을 지금 시작)

QR 한 번으로 연결하고 폴더 선택을 없애는 것이 목표다. 아래를 각각 시험한다.

| 항목 | 내용 | 근거·위험 |
|---|---|---|
| P-a 지원 범위 | 우선 보장할 Android 버전·녹음 앱 조합(갤럭시 기본 녹음 앱부터) | 다른 앱 오디오는 MediaStore에 등재돼야 `READ_MEDIA_AUDIO`로 접근(https://developer.android.com/training/data-storage/shared/media). 등재 안 되는 앱은 SAF·공유 메뉴를 "수동 경로"로 제공 |
| P-b 기준 목록 | 첫 연결 시 기존 녹음 목록을 저장, 기본은 보내지 않음 | — |
| P-c 녹음 완성 판정 | 녹음 중 파일을 올리지 않음 | 삼성 앱의 녹음 중 파일 쓰기 방식은 아직 미확인(`contract.md` 추정 항목) |
| P-d 업로드 큐 | 영속 큐, 해시 확인, 중복 방지, 이어 올리기 | — |
| P-e 백그라운드 | 재부팅·절전·권한 회수·네트워크 변경 | 장시간 작업은 알림·foreground service와 OS 제한이 따름(https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running) |
| P-f 전송 조건 | "같은 와이파이"가 아니라 **페어링된 Mac과 인증된 연결이 가능한가** | 집 밖 전송은 이후(중계·Tailscale) |
| P-g 상태 표시 | 폰에서 "전송 완료"와 "회의록 완료"를 구분, 결과 링크·실패 표시 | — |
| P-h 배포 | Play 스토어 또는 APK | 권한 사용이 API상 가능한 것과 Play 심사 통과는 별개 |

## 5. 엔진 계약 (구현 전에 고정)

### 5.1 작업 실행 모델

- 실행자는 **하나**다. 스케줄러·API는 반응성을 유지하고, 작업은 단일 실행자가 원자적으로 가져가(claim) 순서대로 처리한다.
- DB 연결은 실행 단위별로. 작업 시작 때 그때의 설정을 **스냅샷**으로 저장해, 처리 중 설정을 바꿔도 그 작업은 일관되게 끝나고 다음 작업부터 새 설정이 적용된다.
- 모델 단계는 지금처럼 별도 프로세스. **단계별 제한 시간**, 시간 초과 시 자식 프로세스 종료·회수, 진척 신호(살아 있는지와 일하는지를 구분).
- 감독자는 OS 하나(Mac은 launchd). 엔진의 자기 재시작과 OS 재시작을 겹치지 않는다. 기존 1분 주기 에이전트는 내리고 실행자 하나로 이행한다.
- 지원하는 운영 형태를 명시한다: (a) 로그인한 개인 Mac — 첫 출시 보장 범위, (b) 재부팅 후 로그인 전에도 도는 전용 서버 — 별도 결정(11절). 자동 로그인을 보안 대가 없는 기본 해결책으로 권하지 않는다.

### 5.2 단계 산출물과 캐시 무효화

- 단계 산출물마다 메타데이터: 입력 해시, 언어(감지값·고정값), 백엔드·모델 리비전, 프롬프트·양식 버전, 생성 시각, 완료 여부. 모든 산출물은 임시 파일 → 원자적 rename(지금 `summary.md`만 직접 쓴다).
- 재처리 종류:
  - **이어서 처리**: 메타데이터가 맞는 산출물은 재사용.
  - **처음부터(전사부터)**: 받아쓰기 이후 파생 산출물 무효화.
  - **요약만 다시**: 분류·요약·렌더만 무효화.
  - 언어 고정을 바꾸면 받아쓰기부터 무효화.
- 새 산출물이 완성되기 전에는 기존 정상 결과를 지우지 않는다.

### 5.3 DB 스키마와 이행

- `schema_version`을 두고 이행 스크립트를 순서대로 적용, 적용 전 백업. 중단돼도 다시 돌릴 수 있게.
- 작업 상태 전이표(허용되는 전이만): 발견 → 안정 확인 → 대기 → 실행(단계) → 완료 / 재시도 대기 / 최종 실패 / 건너뜀. "건너뜀 → 대기"는 원본 존재 확인 → 새 정책으로 재검증 → 아카이브 생성 → 전이 순서로만(지금 `backfill`은 이미 건너뛴 파일을 다시 처리하지 못한다).
- 단계별 LLM 제공자 이력은 구조화된 행으로 저장(지금은 문자열 정규식으로 추출).

### 5.4 백엔드 출력 계약

| 단계 | 입력 | 출력 |
|---|---|---|
| `diarize` | 16kHz mono PCM WAV | `[{start, end, speaker}]`, 초 단위, 겹침 허용 여부 명시. 화자 라벨은 공통 계층이 S1…로 정규화 |
| `transcribe` | 같은 WAV, 언어 | 단어 단위 `[{start, end, text}]`. 강제 정렬까지 이 단계 책임 |
| `second_pass` | 같은 WAV, 언어 | 단어 단위, 교정 참고용 |
| `detect_language` | 같은 WAV | 언어 후보와 점수, "불확실"·"지원 외" 표현 가능 |

빈 음성·침묵 구간·오류·모델 식별자 표기를 계약에 포함한다. 플랫폼별 의존성(MLX는 Mac만), 잠금(`fcntl`), 서비스 등록, Syncthing 설정 경로는 플랫폼 어댑터로 분리한다.

### 5.5 언어

- 앞 30~60초만 보지 않는다. **음성이 있는 구간을 녹음 전체에서 여러 개 표집**해 판정한다(앞부분 영어 인사 후 한국어 본회의, 중간 전환 대비).
- 네 가지를 분리한다: 감지된 언어, 사용자 고정값, 노트 출력 언어, 화면 언어.
- 감지 점수가 보정된 확률인지 확인되기 전에는 "정확도 %"처럼 표시하지 않는다.
- 판정 규칙과 기대 결과를 먼저 정한다: 침묵, 한영 혼용(코드 스위칭), 후반 언어 전환, 지원 외 언어.

### 5.6 노트 스키마

- **언어 중립 기계 키 + 표시 번역**: 속성 키와 값 목록(유형·구분·상태)은 영어 기계 ID로 고정하고 `schema_version`을 둔다. 한국어 사용자는 Bases 보기의 열 이름·노트 본문이 한국어로 보인다.
- 이 결정은 지금 볼트의 한국어 속성(`날짜`, `유형` 등)과 다르다. 기존 노트는 **사용자 동의·백업을 거친 일회성 이행**으로 옮기고, 이행 경계 이후에는 구형 키 호환 분기를 늘리지 않는다. 한국어 키를 계속 원하는 사용자가 있는지 확인한다(11절).
- **사용자 소유 필드 보존**: 재요약·재렌더는 생성 영역만 바꾼다. 상태, 참석자, 프로젝트, 할 일 체크, 사용자가 쓴 메모는 보존한다(생성 영역 표식으로 구분).
- 근거 링크: ID는 가변 길이(1000줄 이상), 문장·항목별 참조 유효성 검사. 없는 ID를 **조용히 지우지 않고** 검토 필요로 표시한다. 링크가 있다는 것과 내용이 맞다는 것은 별개라고 화면·문서에 쓴다.

### 5.7 LLM 제공자

- 대상: Codex, Claude, Gemini CLI, Ollama. 지금 대체 경로인 `agy`는 유지 여부를 정하고 설정·테스트·문서를 함께 이행한다.
- 교정·분류·요약 **단계마다** 구조화 출력, 취소, 제한 시간, 인증 만료, 입력 길이 초과, 대체 경로 동작을 계약으로 정한다. 제공자 순서는 설정에서 받아 모든 단계에 전달한다.
- **무도구 동작**: 읽기 전용 샌드박스 = 도구 실행 없음이 아니다. CLI 버전별로 도구·MCP·사용자 설정 로딩을 막는 방법을 조사해 적용하고, 무해한 미끼 파일 읽기·외부 요청·파일 쓰기 시도로 별도 시험 환경에서 확인한다. 확인 못 한 제공자는 화면에 표시. 프롬프트는 stdin으로, 환경 변수는 필요한 것만 넘긴다.
- **외부 전송 판정**: 제공자 이름이 아니라 실제 접속 위치와 모델 실행 위치로(Ollama도 클라우드 모델이 있다, https://docs.ollama.com/faq). **로컬 전용 모드**에서는 외부로 넘어가는 대체 경로를 금지한다. 경계를 넘는 대체는 사용자가 미리 고른 범위에서만. 보내는 필드(대화록, 파일명, 프로젝트 목록)를 알리고 작업별 실제 제공자 이력을 남긴다.
- **Ollama 메모리**: 순서대로 돌려도 Ollama 모델은 기본 잔류 시간 동안 메모리에 남는다. 엔진 요청에 `keep_alive: 0`을 쓰고, 사용자의 다른 Ollama 작업은 건드리지 않는다. 연속 두 작업 메모리와 긴 녹음 입력 예산을 실측한다.

## 6. 입력 처리 방침

| 입력·사건 | 방침·상태 | 필요한 증거 |
|---|---|---|
| 지원 형식(m4a, 이후 mp3·wav) 정상, ko/en | 안정·업로드 확정 뒤 한 번 처리 | 합성 테스트 + 허가된 실제 입력 |
| 5분 미만 | 건너뜀(too_short), 사용자가 명시적으로 처리 가능 | 경계 길이 |
| 과거 녹음 | 기본 수신·처리 제외, 사용자가 고른 것만 승격 | 첫 연결, 이미 건너뛴 작업 각각 |
| 통화·하위 폴더·링크·미지원 확장자 | 수집 제외, 업로드는 명시적 거부 | 새 입력 경로가 기존 제외를 우회하지 않음 |
| 0바이트·전송 중 | 처리하지 않고 대기 상태와 사유 표시, 완료·폐기 조건 정의 | 파일 성장·전송 중단 후 재개 |
| 손상·위장·외부 참조 컨테이너 | 격리·거부, 제한 시간 있는 probe | 외부 요청·장시간 점유·원본 변경 없음 |
| 크기·길이·디스크 한도 초과 | 조기 중지, 부분 업로드 정리, 사유 표시 | 경계값, 동시 업로드, 공간 부족 |
| 같은 해시 / 같은 이름 다른 내용 | 전자는 중복 무시, 후자는 별개 처리 | — |
| 침묵·잡음·지원 외 언어 | 빈 회의록·확신 판정 금지, 사유 표시 | 해당 표본 |
| 지시문·권한 사칭·HTML·링크 | 데이터로 처리, 도구 실행·외부 리소스 로딩 차단 | 프롬프트 단위 테스트 + 격리 CLI 시험 |
| 잘못된 LLM JSON·중복 ID·없는 근거 | 검증 실패 또는 검토 필요, 성공으로 숨기지 않음 | 제공자 계약 테스트 |
| 재부팅·인증 만료·연결 끊김 | 상태 보존, 복구 동작 표시 | 강제 중단, 재로그인, 재연결 |

받는 폴더(inbox)는 계속 **읽기만** 한다. 파일을 옮기거나 지우면 Syncthing이 그 삭제를 폰 원본에 되돌릴 수 있다(https://github.com/surfnterd/syncthing-partial-recordings). 모든 입력 경로(Syncthing, 업로드, 기존 녹음 승격)는 같은 검증 계약을 거친다: 스트리밍 수신 크기 한도 → 격리 임시 저장 → 제한 시간 있는 probe·디코드 → 길이·해시 확인 → 원자적 확정. 일부 형식은 수신이 끝나야 길이를 알 수 있으므로 "받는 도중 길이 한도"는 약속하지 않는다.

## 7. 보안·개인정보

- **로컬 화면·API**: localhost라도 인증한다(로컬 세션). Host·Origin 검사, CSRF 방어, 제한된 CORS, 상태를 바꾸는 GET 금지, CSP, 로컬 자산만. 화면에 보이는 Markdown·HTML은 정화하고 외부 이미지·링크 요청을 막는다.
- **같은 네트워크 접근(선택)**: 전송 암호화, 장치 신원 확인, 장치별 토큰·권한·폐기·재페어링. QR의 일회용 비밀은 짧게 유효하고 한 번만 장기 장치 인증으로 교환하며, URL·로그에 남기지 않는다. 폰 업로드 권한으로 Mac 설정을 바꿀 수 없다.
- **데이터 범위 문구**: "오디오는 사용자가 고른 기기 사이에서만 이동하고 외부 AI 제공자에는 보내지 않는다." 대화록 글자가 어디로 가는지는 단계별 실제 제공자 기준으로 설정 화면과 각 회의록에 표시.
- **보존·삭제**: 원본(아카이브), 작업 중간물(WAV·대화록), 노트, 로그, 백업별 위치·보존 기간·삭제 범위를 문서화하고, 화면에서 처리 일시정지·녹음 제외·로컬 데이터 삭제 제공. 로컬 삭제가 Syncthing 원본이나 외부 제공자 보존에는 미치지 않는다고 알린다.
- **업무/개인 전송 정책은 전송 전에**: LLM이 업무로 분류한 뒤가 아니라, 사용자가 정한 규칙(예: 로컬 전용 모드)으로 보내기 전에 적용한다.
- **동의**: 첫 실행의 한 번 확인으로 끝내지 않고, 녹음 동의·회사 정책 안내를 설정·도움말에서 다시 볼 수 있게. 지역별 법은 법률 검토 전 단정하지 않는다.
- 알림·로그에 회의 제목·대화 내용·토큰을 불필요하게 넣지 않는다.

| 초심자 설치 | (a) Homebrew·CLI 없는 깨끗한 Mac 계정 (b) 준비된 개발자 상태로 나눠 시험. 개발자가 아닌 사람 1명 이상. 손 작업 시간, 총 대기 시간, 도움 요청, 막힌 곳 기록 | 일반 출시 기준(2.1). "막혔지만 문서화"는 합격이 아님 |

| 언어 감지 | ko, en, 혼용, 앞부분만 다른 언어, 침묵 표본. 5건씩은 탐색 자료이지 보장이 아님 | 판정 규칙대로 동작 |
| 제공자 | 4종을 실제 인증 환경에서 교정·분류·요약 각각, 실패 동작, 무도구 시험 | 미설치·미시험은 "지원" 표시 안 함 |

| 입력 방침 | 6절 표의 행마다 테스트와 증거 연결 | 모든 행 |
| 이행 | 구형 노트(`job_id`), 현행 한국어 노트, 사용자가 이름·속성을 바꾼 노트, 사용자 수정 후 재요약, 이미 건너뛴 녹음 재처리 | 사용자 수정 보존, 데이터 손실 없음 |

성능 수치를 낼 때는 측정 환경, 반복·변동, 캐시 조건, 전체 경로 포함 여부를 같이 쓴다. 실제 입력으로 확인 / 가정으로 확인(단위 테스트) / 실행만 을 항목별로 나눠 기록한다.

## 12. 위험

- 폰 연결은 Syncthing을 쓰는 한 사용자 손을 완전히 없앨 수 없다. S1·S2 결과가 출시 경로를 바꾼다.
- 구독 CLI의 약관·출력 형식·로그인·도구 차단 방식이 바뀔 수 있다. 제공자별 시험을 마법사와 주기 점검에 넣는다.
- 16GB Mac에서 Ollama 요약은 품질·메모리가 불확실하다. 실측 전에는 "실험적".
- 상주 서비스는 멈춤·누수가 새 위험이다. 모델은 별도 프로세스, 단계 제한 시간, 감독자 하나.
- 노트 스키마 이행은 사용자 볼트를 바꾼다. 동의·백업·미리보기 없이 하지 않는다.
- 제품 게이트 미결: `contract.md`의 launchd Codex 로그인 동작은 2026-11-09 실제 처리 기록으로 닫았다(무도구 동작·새 서비스의 KeepAlive 검증과는 별개). 삼성 앱의 녹음 중 파일 쓰기 방식은 S2(P-c)에서 2026-11-10 18:00 KST 확인 예정. 표본은 `samples/`(비공개)에 있으며 공개용 표본은 권리 확인된 것으로 따로 만든다.
