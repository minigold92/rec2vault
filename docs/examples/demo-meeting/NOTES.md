# demo-meeting: 가상 회의 한 건을 파이프라인으로 끝까지 돌린 기록

> 이 폴더의 음성은 **합성 음성**(macOS `say`)입니다. 사람 목소리와 다르므로 아래 받아쓰기·화자 분리 수치는 **실제 회의 성능을 뜻하지 않습니다.** 파이프라인이 각 단계에서 무엇을 만드는지 보여 주는 예시이며, 표본은 이 한 건입니다.

## 무엇이 어디에 있나

## 어떻게 만들었나

1. 대본을 `say`의 한국어 목소리 3개로 발화별 합성하고 0.7초 간격으로 이어 붙인 뒤 AAC로 인코딩했습니다: 한다온=Yuna, 오지안=Eddy, 문태오=Shelley.
2. **Mac mini에서는 합성하지 못했습니다.** SSH 세션의 `say`가 일곱 목소리 모두에 똑같은 오디오(Yuna)를 냈습니다(같은 문장 결과 해시가 전부 동일). 그래서 이 MacBook에서 합성했습니다. 이 MacBook에서는 목소리마다 결과가 달랐습니다(같은 문장 기본 음높이 약 Eddy 125 Hz / Shelley 190 Hz / Yuna 265 Hz, 자체 측정).
3. 파일을 Mac mini 별도 루트 `~/rec-demo`의 inbox에 넣고 격리 실행했습니다.
   `REC_SETTINGS=/dev/null REC_ROOT=$HOME/rec-demo REC_OUTPUT=$HOME/rec-demo/notes REC_MIN_DURATION_SEC=60 REC_STABLE_SEC=0 HF_HUB_OFFLINE=1 .venv/bin/python -m rec.tick` (앱 코드는 `~/rec/app`에서 읽기만 함, REC_SINCE 미설정)
4. 산출물을 복사한 뒤 `~/rec-demo`는 지웠습니다. 로그에 `no Syncthing folder contains …/rec-demo/notes` 경고가 있는데, 격리 폴더가 Syncthing 폴더가 아니라서 동기화 알림을 건너뛴 정상 동작입니다.
5. Codex CLI 호출: 교정 1회, 분류 1회, 요약 1회(처리 기록 `correct 0-15: codex`, `classify: codex`, `summary: codex`).

## 받아쓰기: 대본과 비교 (대본이 정답)

문자 오류율(CER) = 편집 거리 ÷ 정답 글자 수. 공백·문장부호를 지우고 비교했고, 정답의 "38퍼센트"는 "38%"로 맞춰 계산했습니다(맞추지 않으면 각 +0.3%p 안팎). 정답 679자 기준.

| 대상 | 오류 글자 | CER |
|---|---|---|
| Qwen3-ASR (`asr.json`, 교정 전 `turns.json`도 같은 글자) | 66 | 9.7% |
| Whisper turbo (`alt.json`) | 22 | 3.2% |
| 교정 후 (`corrected.json`) | 14 | 2.1% |

이 합성 음성 한 건에서 보조 받아쓰기(Whisper)가 주 받아쓰기보다 정확했습니다. 일반화할 수 없는 결과입니다.

교정 후에도 남은 차이(대본 대비):

- 문태오 → **문채호**(자기소개 줄), **태호**(마지막 줄 호명). 사람 이름 오인식이 두 번 모두 교정되지 않았고 요약의 `확인 필요`에 "태호 님이 S3을 가리키는지 확인 필요"로 올라왔습니다.
- 12번 줄 첫 단어 "시안은" → **"기한은"**: 교정이 의미를 바꾼 오류입니다. 같은 "기한은"이 앞 발언(`t010`) 끝에도 붙어 있습니다(ASR 원문은 "귀하는"). 요약의 할 일 기한 항목은 맞게 나왔습니다.
- "에이피아이" → "API", "크기" → "글씨", "알려주는" → "알려드리는": 표기·말투 차이로, 뜻은 유지됩니다.

고유명사·영어 용어 결과: 「책마루」는 ASR·교정 모두 맞았고(Whisper는 "랩책마루"), 「피그마」「온보딩」「푸시 알림」도 교정 후 맞았습니다. 「38퍼센트」는 ASR 원문이 "38"(퍼센트 누락)이고 교정이 "38%"로 고쳤습니다.

## 교정 전후가 달라진 줄 (`turns.json` → `corrected.json`, 16발언 중 10줄)

| 줄 | 교정 전 → 후 (요지) | 판정 |
|---|---|---|
| t002 | 소보르를 / 문채오 → 서버를 / 문채호 | 서버를 맞음, 이름은 여전히 틀림 |
| t003 | 38였습니다 → 38%였습니다 | 맞음 |
| t004 | 그렇게 만났군요 → 그렇게 많았군요 | 맞음 |
| t006 | 홈 화면 메뉴칸에 대출 연장을 … 소독 → 홈 화면 맨 위 칸에 내 대출 현황을 … 저도 좋다고 생각합니다 | 내용은 대본과 일치. 단 "저도 좋다고 생각합니다"는 실제로 문태오의 말인데 화자 분리 오류 때문에 오지안의 발언에 들어감 |
| t007 | 소자 동생답니다 사만이온 야무스는 무료수정 API입니다 무료면 → 다만 연장 버튼을 눌렀을 때 API 응답이 느리면 | 맞음 |
| t009 | 사만 → 다만 | 맞음 |
| t010 | 귀하는 ×2 → 기한은 ×2 | 첫 번째는 맞고, 두 번째는 12번 줄의 "시안은"이어야 함(오류) |
| t012 | 같이 과 주세요 → 같이 봐 주세요 | 맞음 |
| t013 | 귀하는 … 크리버전 … 보시 아시므로 안나비르라요 저는 기능은 → 시안에 … 글씨 버전 … 푸시 알림으로 반납일을 알려드리는 기능은 | 대본과 일치(글씨는 "크기"의 오류). 이 구간은 ASR 원문이 거의 의미를 잃은 부분 |
| t016 | 태오 님은 … 귀하는 나중에 → 태호 님은 … 기한은 나중에 | 기한은 맞음, 이름은 틀림 |

달라지지 않은 줄: t001, t005, t008, t011, t014, t015.

## 화자 분리가 대본의 화자 전환과 맞았나

대본의 화자 전환은 18번, 파이프라인이 만든 발언(turn)은 16개입니다. `diarize.json`은 화자 3명(0/1/2)을 냈고 번호는 한다온=0, 오지안=1, 문태오=2로 대응합니다.

- 분리가 내놓은 구간만 보면(0.05초 단위 비교, 대본 구간과 겹치는 111초) 화자 일치는 **94.3%** 입니다. 다만 이 수치는 틀린 6초(5.7%)와 **분리 결과가 아예 비어 있는 구간을 뺀 값**입니다.
- 대본의 말하는 시간 143.3초 중 분리 결과가 덮은 시간은 111.3초(약 78%)입니다. 빈 구간은 주로 문태오가 말하는 곳입니다.
- 문태오의 발화 5줄(3·8·10·15·19번) 중 10번만 문태오(화자 2)로 분리됐고, 3·15·19번은 오지안(화자 1)에 합쳐졌으며, 8번(10.3초)은 분리 결과에 거의 없습니다(58.6~70.8초 사이가 거의 통째로 비고 0.1초만 화자 2로 표시).
- 한다온(진행)과 오지안은 줄 단위로 전부 맞았습니다(한다온 9줄, 오지안 6줄 — 구간 겹침 최다 화자 기준).
- 결과적으로 `turns.json`에서 문태오의 자기소개(3번 줄)가 오지안 발언(`t002`)에 붙었고, 문태오의 "저도 좋다고 생각합니다"가 오지안 발언(`t006`)에 붙었습니다. 파이프라인은 이를 `split_suspect: true`와 요약의 "화자와 발언 내용의 대응이 불명확함"으로 스스로 표시했습니다.
- 사회자의 "오지안 님" 소개 줄은 요약·노트에서 S2의 이름 추정(`오지안(추정)`)으로 이어졌습니다. 이름은 소개받은 사람이 아니라 S2에 붙었는데, 이 대본에서는 S2가 실제로 오지안이라 우연히 맞았습니다. 문태오는 화자 이름이 비어 있습니다(S3: "API 응답 시간 측정 담당").

## 요약·노트가 대본 속 심어 둔 내용을 잡았나

- 결정: 잡음("홈 화면 첫 칸을 내 대출 현황으로 변경, 대출 연장 버튼 포함"). 푸시 알림·온보딩 제외까지 결정 사항 3줄로 나눠 적음(대본도 이 둘을 범위에서 뺀다고 말함).
- 할 일 2개: 잡음. 시안은 "담당: S2 / 기한: 다음 주 금요일까지", 응답 시간 측정은 "담당: S3 / 기한: 미정"으로 적히고 `미해결`에도 올라옴. 담당은 이름이 아닌 화자 번호로 적힘.
- 수치 38%: 잡음. 금요일은 "다음 주 금요일"로만 적히고 날짜(11-20)로 환산되지 않음.
- 요약의 `[t0NN]` 근거 번호가 모두 맞는지는 전수 확인하지 않았습니다.

## 검증 수준

- **실제 실행으로 확인**: 위 파이프라인 전 단계(변환~렌더·`result.json`)가 합성 음성에서 오류 없이 한 번에 끝남, 단계별 시간, 대본 대비 CER, 화자 일치율, 운영 데이터 불변.
- **가정으로 확인**: 없음.
- **실제 입력으로 확인**: **하지 못함.** 사람이 말한 회의가 아니라 합성 음성 1건이며, 위 수치는 사람 음성·여러 화자·소음에서의 성능을 말해 주지 않습니다.
- **확인 못 함**: Mac mini에서 목소리별 합성(세션 제약으로 불가), 다른 합성 음성·여러 건 반복, 요약 근거 링크 전수 검증.
